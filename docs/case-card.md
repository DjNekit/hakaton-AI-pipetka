## Задача

**Проблема.** Сотрудники тратят много времени на ручную проверку комплекта документов; ОИВ сталкивается с проблемами
из-за ошибок при проверке.

**Целевой результат за 8 часов.** MVP с простейшим графическим интерфейсом.

**Исходные данные от организаторов.** НПА и ссылки на утверждённые архитектурно-художественные концепции г. Москвы.

**Критерии приёмки.**
- точность проверки комплекта документов — не менее 85 %;
- точность сравнения графической части с фото/скрином — не менее 95 %;
- код в открытом репозитории;
- простой интерфейс.

**Ограничение.** Отечественные модели. Облачные сервисы допускаются.

**Общая постановка.** Прототип интеллектуальной системы, которая проверяет комплект документов на соответствие НПА,
обрабатывает фотографии и/или скриншоты с камер видеонаблюдения (распознавание фасада здания), сравнивает рендеры
из документов с фото/скрином и выдаёт вывод о соответствии внешнего вида здания.

### Комплект документов

**Пояснительная записка:**
- описание существующего состояния объекта и проектного колористического решения фасадов;
- для рекламных вывесок: адрес, тип вывески, способ освещения; материалы, колористические и технические решения,
  заглубление отдельно стоящей конструкции / ценового табло АЗС; материалы по уникальным информационным конструкциям,
  исторический облик которых определён архитектурным проектом здания.

**Графическая часть:**
- ортогональные чертежи фасадов в М 1:500 / 1:200 / 1:100 / 1:50 с адресом объекта и автором колористического решения;
- для рекламных вывесок: фотофиксация с датой; фотомонтаж (врисовка вывески в существующую ситуацию); ортогональные
  чертежи фасадов с местами вывесок, в т. ч. из утверждённой архитектурно-художественной концепции; экспликация вывесок.

После строительно-монтажных работ результат сравнивается с рендерами из графической части: инспектор фотографирует
здание или делает скрин с городской камеры.

**Ключевой фокус:** доказать ценность автоматической проверки документов на соответствие НПА и сопоставления снимков
с рендерами, показать понятный механизм выявления отклонений, заложить основу для развития.

### Обязательные функции

1. Распознавание загруженных комплектов документов.
2. Проверка сути комплекта на соответствие правилам НПА.
3. Отчёт об ошибках.
4. Распознавание графической части документов и загруженных фото/скринов с видеопотока.
5. Сравнение фото/скринов с изображениями графической части.
6. Вывод по результатам сравнения изображений (совпадает / не совпадает).

## Применимость

- Плановая задача: проверка паспортов колористического решения зданий.
- После хакатона: доработка подразделением (подрядчиком) и пилот на реальных данных.
- Зрелость: рабочий прототип с простейшим интерфейсом.

## Стек из карточки

Linux; Python 3.10+; Git + GitHub/GitLab; PostgreSQL, MySQL; Docker Compose; Django 4.2, React 18, TensorFlow 2.13,
pandas 2.0; языковые модели (доступ к ИИ-моделям обязателен, облако допускается); распознавание документов и графики,
сравнение графических частей.
