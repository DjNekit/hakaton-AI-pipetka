
# Project Context

## Purpose
Колорпаспорт — прототип ИИ-сервиса автоматической проверки паспорта колористического решения
фасадов (хакатон, кейс 7). Сервис формализует требования к паспорту, анализирует текстовую и
графическую части PDF, находит несоответствия и наглядно показывает их на листах с готовым
заключением.

Целевые пользователи: специалисты, проверяющие паспорта колористических решений (Москомархитектура,
подведомственные организации), и проектировщики, готовящие паспорта к подаче.

## Tech Stack
- Python 3.10+; ядро проверки — пакет `backend/colorpass` (не зависит от веб-фреймворка)
- PDF: pdfplumber (текст, таблицы, векторные примитивы), pypdfium2 (рендер листов)
- Цвет и графика: numpy, OpenCV; собственная реализация CIEDE2000 и sRGB↔Lab
- Веб: Django 4.2 (тонкий REST-слой `backend/api`), React 18 + Vite (`frontend/`)
- ЛЛМ: GigaChat API (облако Сбера), ключ — `GIGACHAT_AUTH_KEY`; без ключа — проверка по правилам
- Тесты: unittest (совместимы с pytest); метрики качества — `python -m colorpass eval`
- Резервный сервер без Django: `backend/devserver.py` (только стандартная библиотека)

## Project Conventions

### Code Style
- Python: PEP 8, type hints, `from __future__ import annotations`; комментарии и сообщения — на русском
- Все пороги и тексты требований — в `backend/colorpass/data/rules.yaml`, не в коде
- JS: функциональные компоненты React, без UI-библиотек; стили — `frontend/src/styles.css`

### Architecture Patterns
- Конвейер: ingest (PDF) → extract (модель паспорта) → checks (правила) → report (JSON + изображения)
- Детерминированное ядро: числа, коды и решения «соответствует / не соответствует» считает код;
  ЛЛМ только читает текст и формулирует заключение, её ответы валидируются по исходному тексту
- Каждое замечание (Finding) содержит правило, лист, bbox в пунктах PDF, ожидаемое/фактическое значение
  и ссылку на пункт НПА
- Отказоустойчивость: недоступность ЛЛМ, падение одной проверки или нераспознанный раздел
  не прерывают проверку — правило получает статус «не применимо» с пояснением

### Testing Strategy
- Реальные паспорта с ручной разметкой в `dataset/real` (сейчас — опубликованный паспорт № 19/04406)
- Модульные тесты: `cd backend && python -m unittest discover -s tests`
- Метрики: recall по заложенным ошибкам (ориентир ≥ 70 %), precision, прохождение «чистых» эталонов

## Domain Context
- Основной НПА: ПП Москвы от 28.03.2012 № 114-ПП «О колористических решениях фасадов зданий,
  строений, сооружений в городе Москве» (ред. от 03.04.2025): прил. 1 — Положение (п. 3 — состав
  проекта), прил. 2 — Административный регламент (п. 2.8.1 — основания отказа в приёме документов),
  прил. 3 — форма Паспорта.
- Структура паспорта (по опубликованному образцу Москомархитектуры): титул; I. Общие сведения;
  II. Градостроительная характеристика; III. Архитектурная характеристика, существующее состояние,
  фотофиксация; IV. Развёртки фасадов; V. Таблица отделки (№, наименование элемента, материал,
  образец цвета, марка цвета по палитрам, примечания).
- Марки цвета указываются по палитрам NCS и RAL одновременно (114-ПП, прил. 1, п. 3.1.2).
- Цветовое отличие оценивается по CIEDE2000 (ΔE00); NCS переводится в sRGB приближённо.

## Important Constraints
- Только тестовые данные; реальные паспорта — только от куратора кейса
- В финальной версии — только отечественные языковые модели (кейс 7); код от модели не зависит
- Проверка одного паспорта без ЛЛМ — секунды, с ЛЛМ — не более нескольких минут
- Работа без интернета: все справочники (RAL, правила) лежат в репозитории

## External Dependencies
- GigaChat API — `GIGACHAT_AUTH_KEY`, `GIGACHAT_MODEL`, `GIGACHAT_SCOPE`; сертификат НУЦ Минцифры (ставится в Docker-образ)
- PostgreSQL — история проверок (`DATABASE_URL`)
- tesseract + pytesseract — опционально, для OCR сканов без текстового слоя
